# Test plan

| Scenario | Steps | Expected | Coverage |
|---|---|---|---|
| Every layer is summarised | Run the reporter's JUnit, self-test, and Qt fixtures and inspect the rendered totals. | Each layer subtotal and the TOTAL match the fixture counts, with exit 0 on the green path. | `scripts/report_tests.py::run_self_check` |
| A failure is listed and fails the run | Run the reporter's failing JUnit and self-test fixtures. | FAILURES names the failed checks and the reporter exits non-zero. | `scripts/report_tests.py::run_self_check` |
| Colour output is selectable | Render the same layer with colour off and on. | `never` emits no ANSI sequence and `always` emits one. | `scripts/report_tests.py::run_self_check` |
| The Qt Test layer is folded in | Run `scripts/test-report.sh` against built Qt suites and inspect the generated JUnit inputs. | CTest runs the registered suites and their counts appear in the unified report. | manual: requires the built CTest layer and the shell orchestration. |
| `tr_qt_parallel` | Run the shell report on a 16-CPU budget and inspect the CTest command. | CTest receives parallel level 12 and one JUnit file per suite. | manual: CPU-budget and process scheduling are shell runtime behavior. |
| `tr_qt_parallel_override` | Run the shell report with `CTEST_PARALLEL_LEVEL=2`. | CTest receives parallel level 2. | manual: requires the shell and CTest runtime. |
| `tr_qt_parallel_floor` | Run the shell report with a one-CPU budget and no override. | CTest receives parallel level 1. | manual: requires a one-CPU affinity slice. |
| `tr_stale_junit` | Leave a stale Qt JUnit file, remove its suite, and run the shell report. | The script removes the stale file before CTest and the report omits it. | manual: requires filesystem and CTest orchestration. |
| `tr_layers_concurrent` | Time the self-test and CTest layers together and separately under the same budget. | Their combined wall time is below the sum, and either failure fails the report. | manual: wall-time overlap is a runtime measurement, not a parser assertion. |
| `tr_single_document_capture` | Inspect and run `scripts/test-report.sh` with a built app. | One self-test process receives `two_layers.psd`, one combined log reaches the reporter, and the log has one final SUMMARY. | manual: process count and invocation arguments are shell runtime behavior. |
| `tr_unique_checks_preserved` | Compare the reporter's synthetic legacy bare-plus-document merge with one combined stream containing two shared checks, `fresh_white`, and 36 document checks. | Both produce the same 39 unique fixture entries and totals; the production set arithmetic remains 466 + 1 + 36 = 503. | `scripts/report_tests.py::run_self_check` |
| `tr_mode_conditional_checks` | Run the app directly in bare mode and with the PSD fixture, then compare check-name order. | Bare mode contains `fresh_white` and no document-only names; the combined PSD invocation contains `fresh_white` before the 36 document-only names. | manual: the mode switch lives in the C++ executable and has no unit seam. |
| `tr_single_summary_authoritative` | Pass one complete stream with a matching SUMMARY through the merge function and the layer builder. | The returned total equals the SUMMARY and entries equal the unique keys. | `scripts/report_tests.py::run_self_check` |
| Push or pull request | Inspect and run the CI workflow on a push and PR. | Required jobs run and any non-zero step fails its job. | manual: CI event and job behavior cannot run in the reporter self-check. |
| A feature-branch push is covered once | Push to a branch with an open PR and inspect the workflow runs. | Build jobs run once through the PR synchronization event. | manual: requires GitHub event delivery. |
| Tests run under nextest | Inspect and run the CI test job. | The workspace runs under nextest with no doctest run. | manual: CI job behavior. |
| Lint and test run in parallel | Start a CI run and inspect job timing. | Lint and test jobs run independently. | manual: CI scheduling behavior. |
| The local fast gate uses nextest | Inspect and run the local fast gate. | It invokes nextest with `--no-fail-fast` and no doctest command. | manual: gate orchestration is outside this change and was not run. |
| The JUnit artifact is uploaded | Complete the CI test job and inspect its artifacts. | `target/nextest/default/junit.xml` is uploaded. | manual: requires CI artifact storage. |
| The Qt app self-tests headlessly | Run the Linux headless CI job and inspect its self-test step. | One `--headless --self-test` invocation includes `two_layers.psd` and fails on non-zero. | manual: requires the CI build and runtime. |
| External oracles are exercised | Run the CI test job with its oracle tools installed. | Oracle tests compare against ImageMagick, `psd-tools`, and `ag-psd`. | manual: external-tool CI behavior is unchanged by this patch. |
| `vh_no_doctests` | Inspect workspace manifests and CI commands. | Every library disables doctests and no command runs them. | manual: static repository contract outside the reporter self-check. |
| Compiled artifacts are reused | Run CI twice with populated caches. | Dependencies and compiled objects are restored. | manual: CI cache behavior. |
| A runaway job is bounded | Inspect CI job definitions and let a controlled job exceed its bound. | CI cancels the job at `timeout-minutes`. | manual: requires CI runtime control. |
| `vh_ci_ctest_parallel` | Run the CI headless job with and without `CTEST_PARALLEL_LEVEL`. | CTest uses the runner CPU count by default, honors the override, and emits every JUnit file. | manual: CI and CTest runtime behavior. |
| `vh_ci_no_pch` | Inspect and run the CI configure and build. | Precompiled headers are disabled and all sources compile. | manual: CI build behavior. |
| `vh_ci_mold` | Inspect and run the CI toolchain setup and link commands. | mold is installed and used for C++ links. | manual: CI toolchain behavior. |
| Real combined capture has 503 unique checks | Run the built self-test with `two_layers.psd` and parse its token stream. | One final SUMMARY reports 503 passed, zero failed, zero skipped, and 503 unique `(suite, name)` keys including `fresh_white` and the 36 document-only names. | manual: requires the built app and committed PSD fixture. |
| Direct bare mode still covers `fresh_white` | Run the built app without a document and parse its token stream. | The capture has 467 checks including `fresh_white` and none of the 36 document-only names. | manual: requires the built app. |
| Failure identity is unchanged | Compare FAIL token codes and process statuses for representative bare and document failures against the pre-change baseline. | Raw codes and status normalization are unchanged. | manual: no failure-injection seam exists without altering checks. |
| Protected self-test surfaces are untouched | Inspect the diff for ST macros, exit-code constants, check bodies, `scripts/selftest-budget.txt`, and the `selftest.cpp` file-size ceiling. | No protected surface changes, the budget remains 503, and `selftest.cpp` remains at 6439 lines. | manual: diff and line-count inspection prove the scope constraint. |
| Overlap measurement is deferred | Execute the design's sequential measurement plan in a later phase. | Record medians, CPU, spread, and flakes before deciding whether nextest overlap ships. | manual: benchmarks are explicitly outside this phase. |
