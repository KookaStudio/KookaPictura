# Test Plan

This plan names the checks to write or extend during implementation. Use
controllable worker barriers, clock advances, and injected I/O failures so
tests can assert ordering without relying on disk timing.

| Scenario | Steps | Expected | Coverage |
|---|---|---|---|
| `dl_save_worker` | Hold a native worker and drive a timer and canvas repaint through the wait. | No timer gap exceeds 50 ms and the canvas paints while the worker is held. | `tst_offthread_jobs::saveKeepsTheEventLoopLive` |
| `dl_save_sync_bytes` | Save identical documents using the synchronous caller and the held interactive path in each native format. | PSD and PSB pairs are byte-identical. | `tst_offthread_jobs::nativeSaveCallersWriteSameBytes` |
| `bs_preference` | Check fresh File Handling settings, switch off background saving, reload the session, and invoke a held native Save. | The default is on, the disabled setting persists, input waits with a busy indicator, and recovery settings are unchanged. | `tst_offthread_jobs::backgroundSavePreferencePersists` |
| `bs_input_progress` | Hold a menu Save after an observable phase, send an edit to the saving tab, and then switch tabs and edit again. | Both edits land. The saving tab has its own percentage, the active document shows its own status, and completion clears the progress. | `tst_offthread_jobs::backgroundSaveAcceptsInputAndShowsProgress` |
| `bs_stale_save_as` | Hold Save As of revision A, edit to B, switch tabs, release the job, and reopen the output. Exercise replacement using the Rust job seam. | File pixels are A, the new path and action record belong to the origin, B stays dirty, and the selected and replacement documents retain their state. | `tst_offthread_jobs::backgroundSaveAsCompletesOnOrigin`, `pictura-app::a_replaced_document_keeps_its_path_and_dirty_state` |
| `bs_previous_saved_state` | Hold a save of A, undo to the prior saved state, complete the write, then redo to A. | The prior disk state becomes dirty once A replaces it, and redo to A clears dirty. | `tst_offthread_jobs::backgroundSaveUpdatesTheSavedHistoryState` |
| `bs_competing_saves` | While one Save As is held, save the same view again and target the same filename through another tab and a path alias. | The first write owns its destination and both conflicts show the notice. | `tst_offthread_jobs::backgroundSaveRejectsConflictingWrites` |
| `bs_durable_failure` | Inject failures before rename and at directory sync after rename through the native job. | File bytes survive the early failure. Early failure preserves live and recovery state; late failure reports uncertainty and protects the live state. | `pictura-app::native_save_distinguishes_publication_failures`, `tst_offthread_jobs::backgroundSaveReportsUnconfirmedPublication` |
| `bs_close_recheck` | Request Close during a held stale or failing save, then choose Cancel in the unsaved-changes prompt. Repeat with Save and a successful write. | The decision follows the pending result, Cancel preserves B, and Save completes before Close. | `tst_offthread_jobs::closeRechecksAfterBackgroundSave` |
| `bs_lifecycle_recheck` | Exercise Revert, quit, and the restart preflight with a held write and an unsaved edit. | Each operation resolves the job, offers the unsaved-changes decision, and preserves the document on Cancel. | `tst_offthread_jobs::destructiveActionsResolveBackgroundSave` |
| Only unsaved changes are snapshotted | Observe a clean document, commit a Work Path, and drain the next checkpoint cycle with no further edit. | The clean document creates no checkpoint, the path round-trips, and the checkpoint is reused. | `tst_recovery::autosaveSnapshotsOnlyUnsavedChanges` |
| Save and close drop the snapshot | Close a dirty document with Discard while its recovery writer is held and durably save a second document. Release all workers. | Both chains and manifests are removed and remain absent after workers finish. | `tst_recovery::saveAndCloseDropTheSnapshot`, `pictura-app::async_retire_fences_pre_and_post_save_captures` |
| `cr_psb_checkpoint` | Make a low-allocation document with dimensions outside PSD limits, edit it, and reopen the checkpoint through recovery. | Header version is 2 and recovery keeps the document dimensions and edit. | `tst_recovery::largeCheckpointUsesPsb` |
| `cr_committed_results` | Commit a stroke, structural edit and metadata change. Exercise undo, redo, jump and snapshot restore before starting an uncommitted gesture and reopening recovery. | Recovered native state equals the last durable committed state and history has one initial entry. | `tst_recovery::journalRecoversCommittedDocumentState` |
| `cr_batched_sync` | Advance the clock while edits arrive without an idle gap. Exercise the size trigger, a refused command and a preview. | Each trigger can sync a batch and no frame records the refused command or preview. | `pictura-app::recovery_batches_sync_during_continuous_edits`, `tst_recovery::journalSkipsUncommittedChanges` |
| `cr_disable_journal` | Switch off recovery with writers held, release them, then edit again. | The old manifest, checkpoint, and journal disappear without being republished. | `tst_recovery::disablingRecoveryDrainsPendingWrites` |
| `cr_write_degraded` | Inject append and sync failures after a durable batch. Restart recovery and inspect the warning. | The durable prefix remains recoverable, the file and live document are intact, and degraded protection is reported. | `pictura-app::journal_io_failure_keeps_durable_prefix`, `pictura-app::older_completion_cannot_clear_newer_capture_failure`, `tst_recovery::journalFailureReportsDegradedProtection` |
| `cr_replay_prefix` | Parameterize a bad checksum, torn payload, oversized length, and broken predecessor. Recover a document with a valid prefix after a PSD round trip adds a merged alpha plane. | The decoder applies only the complete valid prefix, replays layer color edits on the correct planes, and reports the lost tail. | `pictura-app::journal_replay_stops_at_first_invalid_record`, `pictura-app::recovery_delta_keeps_layer_addresses_after_psd_round_trip`, `tst_recovery::journalTailFailureRecoversValidPrefix` |
| `cr_checkpoint_commit` | Interrupt checkpoint publication before and after rename with journal data queued, then repair. | Pre-rename failure preserves the active journal and queue; after rename, appends are fenced until a durable replacement is discoverable and obsolete candidates are removed. | `pictura-app::interrupted_checkpoint_publication_preserves_journal_suffix`, `pictura-app::uncertain_manifest_fences_old_journal_until_new_checkpoint` |
| `cr_legacy_checkpoint` | Create an orphan directly from an unversioned manifest and its PSD using a legacy fixture, then recover. | The document opens dirty and untitled with its original native content. | `tst_recovery::recoverReopensAnOrphanedDocument` |
| `cr_transfer_durable` | Replay an orphan with a valid journal, refuse its new checkpoint, then retry recovery with storage available. | The original chain survives the failure and recovers on retry. | `tst_recovery::failedRecoveryTransferKeepsOrphanChain` |
| `cr_save_race` | Start a held interactive save of A in a child Pictura process, make B durable, release A, then kill the process before exit cleanup. | Reopening the user file yields A and recovering the orphan yields B. | `tst_recovery::staleBackgroundSaveLeavesJournalRecoverable` |
| `cr_power_loss` | On a disposable machine or VM with controlled write caches, cut power during checkpoint publication and immediately after a batch is acknowledged durable. Reboot and recover. | The recovered chain includes every acknowledged edit, with either the previous or the newly published checkpoint. | manual: requires a machine or VM power-loss harness and persistent storage outside the test process |
| `ir_recovery_resources` | Encode both native checkpoint containers with a supplementary Unicode character in the target name and duplicate imported autosave IDs. | Each generated pair occurs once, has the expected Unicode payload, and the remaining blocks are byte-identical. | `pictura-codec::recovery_resources_replace_duplicate_blocks`, `tst_recovery::checkpointResourcesMatchTheContainer` |
| `ir_foreign_recovery_resources` | Round-trip native files both with and without an opaque 1086/1087 pair. | The pair is preserved byte-for-byte when present and stays absent otherwise. | `pictura-codec::ordinary_native_saves_preserve_autosave_resource_bytes` |
| `ir_recovery_discovery` | Point resource 1086 at another readable file and give 1087 the wrong format before recovering through a valid manifest. Save the recovered document. | Manifest and file header determine recovery, and the user file contains neither generated block. | `tst_recovery::generatedResourcesNeverDriveRecoveryOrLeak` |

| Save As writes a file | Run Save As to a chosen path and read the file back | A valid file of that format exists at the path and the document is unmodified | `tst_open_save::chosenFormatWinsOverTypedSuffix`, `tst_document_api::saveAndReopenRoundTrip` |
| Save uses the recorded path | Edit a document with a recorded raster path and run Save | The file at that path is overwritten in place without Save As | `tst_open_save::rasterOpenKeepsFilePath` |
| Save on an untitled document prompts for a path | Run Save on an untitled document | A Save As path is requested before any write | `tst_open_save::untitledSaveRequestsPath` |
| Save after an edit writes the edited composite | Edit a raster document, save it, and reload it | The saved file carries the edited pixels, not the pre-edit merged image | `tst_open_save::rasterOpenKeepsFilePath` |
| Save As defaults to the import source format | Open a single-layer PNG and invoke Save As | The Save As dialog preselects PNG | `tst_open_save::saveAsDefaultsToImportedFormat` |
| A raster save clears modified and re-saves the same format | Save a document to `photo.png`, edit it, and save again | The second save rewrites the PNG and the document is unmodified | `tst_open_save::rasterOpenKeepsFilePath`, `tst_document_api::saveAndReopenRoundTrip` |
| A layered document saved to a flat format warns and flattens | Save a layered document to a PNG and confirm the warning | The flattened composite is written as a PNG | `tst_open_save::layeredFlatSaveWarnsAndFlattens` |

| Save on a layered raster path behaves as Save As | Save a layered document recorded at a `.png` path | The format-aware Save As dialog opens instead of overwriting the PNG | `tst_open_save::layeredRasterSaveOpensSaveAs` |
| A PSB path writes a PSB container | Save a document to a `.psb` path and inspect the header | The written file is a version-2 PSB | `tst_save_options::psbOn` |
| `dl_save_current` | Save a modified document through the worker and reopen the file | The path is recorded, the document is unmodified, and the reopened layers and composite match the snapshot | `tst_offthread_jobs::aCompletedSaveWritesAndClearsModified` |
| `dl_save_stale` | Hold a save in flight, edit the document from a timer, then finish the save | The file holds the snapshot bytes, the path is recorded, and the document remains modified | `tst_offthread_jobs::anEditDuringSaveLeavesTheDocumentModified` |
| `dl_save_failed` | Save to a path whose directory cannot be written | The save returns false, the path and modified state are unchanged, and no temp file remains | `tst_offthread_jobs::aFailedSaveLeavesTheDocumentUntouched` |
| `dl_save_replaced` | Hold a save in flight and replace the document before finishing the save | The file holds the original snapshot and the replacement keeps its own path and dirty state | `pictura-app::a_replaced_document_keeps_its_path_and_dirty_state` |
