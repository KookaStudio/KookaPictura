# Test plan

| Scenario | Steps | Expected | Coverage |
|---|---|---|---|
| `shell_version_flag` | Run `pictura --version` with `QProcess`, an invalid `QT_QPA_PLATFORM`, a temporary state home, and the local test release endpoint. In the Windows packaging smoke check, capture the staged executable's output through a PowerShell pipe and compare it to the checkout's `version.txt`. Review `main()` to confirm the version branch returns before the GPU-probe path. | Status 0 and one `Kooka Pictura <version>` line with the configured version. The `QProcess` check sees empty stderr, untouched state home, and zero release requests. The version branch bypasses GPU probing. | `tst_update_preferences::versionFlagWorksWithoutDisplay` |
| `up_about_version` | Dispatch the About command and inspect the displayed message box. Compare the package method with detection for this run. | The box names `Kooka Pictura <version>` and contains the detected package method. | `tst_update_preferences::aboutShowsVersionAndMethod` |
| `up_system_info_package` | Collect a System Info report for this run and exercise its Copy button. Compare the displayed and copied package lines to the detected package method. | The clipboard contains the exact displayed report, including `Package: <detected method>`. | `tst_system_info::dialogCopiesReport` |
| `up_about_runtime` | Dispatch the About command in a window with no document open and inspect the message box. Compare displayed adapter fields with the renderer bridge summary for that window. | The box shows the CMake build type or `Unavailable` when empty, the exact `qVersion()` value, and the current renderer label. The adapter and driver rows match the bridge values or show `Unavailable` for missing values. | `tst_update_preferences::aboutShowsRuntimeDetails` |
| `up_about_gpu_adapter` | Compare the actual About fields to the renderer bridge summary. Also format the details with a CPU renderer label and a fixture adapter name and driver. | The live fields match available adapter and driver details. The fixture shows the CPU renderer, adapter name, and driver in their own fields. | `tst_update_preferences::aboutShowsRuntimeDetails`, `tst_update_preferences::aboutSeparatesCpuRendererFromAdapter` |
| `up_about_gpu_unavailable` | Check the actual About fields against the bridge summary, including fallback for any missing values. Also format an empty adapter summary and one with a name but no driver. | The renderer remains visible, each missing field reads `Unavailable`, and any known value remains visible. | `tst_update_preferences::aboutShowsRuntimeDetails`, `tst_update_preferences::aboutDisplaysUnavailableAdapterFields` |
