# Test plan

Use independently authored PSD fixtures with original layers, strings, and images. The public originals in the local reference corpus provide black-box observations. The automated suites run with files generated by the project or created by the tests.

| Scenario | Steps | Expected | Coverage |
|---|---|---|---|
| `vars_bindings` | Bind two layers to one visibility variable, rename and reorder one original, and duplicate the other | Both original layers respond. The duplicate keeps its visibility | `pictura-app::variable_bindings_follow_layer_ids` |
| `vars_validation` | Try an invalid name, sharing across kinds, a Background, and incompatible type and raster targets | Each invalid edit reports its reason and preserves the previous store | `pictura-core::variable_bindings_validate_names_and_targets` |
| `vars_delete_undo` | Delete the last bound layer after storing two values, then undo | Deletion removes the binding and unbound variable. Undo restores the layer and both values | `pictura-app::variable_bindings_restore_on_undo` |
| `vars_set_values` | Add and rename a variable, duplicate a selected set, and edit the copy | Defaults are valid, both sets still resolve the renamed variable, and the original values survive | `pictura-core::variable_data_sets_keep_typed_values` |
| `vars_set_linked_defaults` | Bind layers with differing text and visibility, arrange them across a group, and create a set with no selection | The first eligible bound layer in recursive top-to-bottom stack order supplies each default | `pictura-core::variable_linked_defaults_follow_stack_order` |
| `vars_apply_undo` | Apply a mixed set, inspect layers and history, then undo and redo | One named entry changes all three kinds. Editable type and modeled style survive, and history restores both states | `pictura-app::variable_apply_is_one_edit` |
| `vars_empty_text` | Apply an empty text value and save and reopen the document | The saved layer remains editable, with empty contents and no rendered glyphs | `pictura-app::variable_empty_text_stays_editable` |
| `vars_skip_pixels` | Apply a replacement and then a set containing only Do Not Replace | The already-applied pixels and the history head are unchanged | `pictura-app::variable_skip_keeps_current_pixels` |
| `vars_apply_atomic` | Mix an early valid change with a missing file and, separately, an invalid layer type | The failed variable is reported. The document, selection, and history head match the pre-Apply state | `pictura-app::variable_apply_failure_is_atomic` |
| `vars_pixel_placement` | Place a non-square transparent source into an offset layer for all methods, anchors, and eligible clip states | Geometry and edge alpha are correct. Layer identity, effects, and mask survive | `pictura-render::variable_pixel_placement_respects_frame` |
| `vars_native_pixels` | Apply replacements to 16-bit RGB and a supported non-RGB raster document and reopen the output | Mode and depth survive, replaced channels are current, and old native samples are not restored | `pictura-app::variable_pixels_save_in_native_encoding` |
| `vars_empty_frame` | Apply a replacement file to a zero-area raster layer | Error with no history state or geometry change | `pictura-app::variable_empty_frame_is_refused` |
| `vars_psd_read` | Read a generated Photoshop-style template with mixed traits, shared bindings, Unicode and a replacement path | Typed values, layer IDs and placement options match fixture values | `pictura-codec::psd_variables_read_mesa_templates` |
| `vars_psd_preserve` | Open individually malformed, unsupported, stale-ID, and ambiguous-ID variants, then resave after an unrelated edit | Safe values resolve, affected XML remains byte-identical, and destructive edits to it are refused | `pictura-codec::psd_variables_preserve_unsupported_blocks` |
| `vars_psd_ratio` | Generate independently derived `ratio` / center / middle / unclipped resource bytes with a source and frame of differing dimensions matching the public observation | The reopened binding applies centered As Is at source dimensions without clipping | `pictura-app::psd_variables_ratio_as_is` |
| `vars_psd_unknown_placement` | Read independently derived resource bytes containing an unconfirmed token and an unconfirmed `ratio` option combination, save after an unrelated edit, and reopen | Each affected binding remains unresolved and reported; its bytes survive unchanged | `pictura-codec::psd_variables_preserve_unknown_placement` |
| `vars_psd_duplicate_ids` | Open a generated template with layer comps and duplicate original layer IDs referenced by a variable, save unrelated edits, and reopen | Both opens report ambiguity without choosing a layer; source ID blocks and dependent resources survive | `pictura-codec::psd_variables_preserve_duplicate_ids_with_comps` |
| `vars_psd_roundtrip` | Author all three kinds with layer comps absent and save to PSD and PSB, then reopen and allocate another layer ID | Bindings, values, and placement survive in `MeSa` blocks. The ID seed keeps allocation collision-free | `pictura-codec::psd_variables_roundtrip_without_layer_comps` |
| `vars_psd_rewrite` | Save a combined variable and image-resource edit, remove all variables, then save again | Initial edits survive together. Removing variables clears authored resources and preserves unrelated blocks | `pictura-codec::psd_variables_rewrite_resources_selectively` |
| `vars_import_syntax` | Parse CSV and TSV input across supported encodings and line endings with external spaces and quoted separators, quotes, and breaks | Required field text and typed values match in each supported case | `pictura-app::variable_import_reads_delimited_encodings` |
| `vars_import_names` | Reorder declared headers, choose first-column names, and attempt to add an unmatched naming column | The first cell doubles as the actual value and the set name. The extra column fails validation | `pictura-app::variable_import_first_column_is_a_binding` |
| `vars_import_atomic` | Replace an existing collection using input with a later malformed row, wrong width, invalid value, or duplicate set name | The error identifies the failure and the existing data stays intact | `pictura-app::variable_import_failure_preserves_sets` |
| `vars_import_commit` | Append and replace from a file with a relative image path, save elsewhere, reopen, and undo the import in the original session | Path meaning persists, generated names stay unique, and undo restores the previous collection | `pictura-app::variable_import_commits_once_and_keeps_paths` |
| `vars_import_single_column` | Import one-column CSV, TSV, and TXT, including an unquoted comma in TSV; try an unknown extension and a mixed-delimiter header | Extension chooses the delimiter, TSV comma survives, and ambiguous or unknown formats leave sets intact | `pictura-app::variable_import_single_column_delimiters` |
| `vars_export_outputs` | Export two of three sets with a replacement in the first and Do Not Replace in the second | Exactly two PSDs reopen, preserve editable layers and metadata, and use their own set against the initial template | `pictura-app::variable_export_uses_a_fresh_baseline` |
| `vars_export_names` | Export a pattern with unsafe characters, long UTF-8 names, collisions, and existing files | Unique bounded names stay in the destination, with existing file bytes intact | `pictura-app::variable_export_avoids_path_collisions` |
| `vars_export_errors` | Inject missing replacement, invalid target, unsupported mode or conversion, allocation rejection, invalid destination, write failure, and cancellation after an output | Skips and stops are reported by case. Completed PSDs reopen, partial writes are absent, and the source is untouched | `pictura-app::variable_export_failure_keeps_completed_files` |
| `vars_commands` | Inspect command availability in an empty frame, a document, a variable template, a template with a set, and a blocking edit | Action state and dispatch match each stage | `tst_variables::commandsTrackTemplateState` |
| `vars_desktop_open` | Open the same supported template through desktop Open and the eager loader, then inspect commands and variable values | Lazy desktop Open exposes the same resolved bindings and sets and enables the same commands | `tst_variables::desktopOpenLoadsTemplateMetadata` |
| `vars_dialog_edit` | Define, switch pages, edit or import values, accept, and undo | One history entry covers the staged changes, and undo restores the previous store | `tst_variables::definitionAndSetCommitTogether` |
| `vars_dialog_cancel` | Stage a definition and in-dialog import, preview it, then switch pages and cancel | Store, canvas, dirty state and history match the original | `tst_variables::cancelDiscardsStagedEdits` |
| `vars_preview` | Preview a replacement and then a Do Not Replace set, toggle Preview off, and cancel | The second preview and the restored canvas match the original baseline. History and dirty state are unchanged | `tst_variables::previewSwitchAndCancel` |
| `vars_export_dialog` | Open the export sheet, exercise destination, naming and set selection, then cancel | Expected controls are operable and no file is written | `tst_variables::exportDialogCancelsWithoutWriting` |
