# Test plan

This plan is for the diagnostic prerequisite only. New test names are apply
work, not existing coverage claims. No test here claims the reported latency
is fixed. Default checks use small generated inputs; large engine/application
profiles are ignored with an explicit invocation reason. No external document
is required by normal tests. Timing acceptance is tested with fabricated
reports, not unstable default-suite wall-clock assertions.

| Scenario | Steps | Expected | Coverage |
|---|---|---|---|
| `cfc_profile` | Launch fresh engine-profile children for generated layered inputs; collect decode, first full, warm repeats, region, nested phases, and digests. Feed the report builder a deliberately slow first value, faster warm values, absent phases, and a slow digest hook. | The first value remains independent; raw samples, absent versus zero phases, nesting, digest exclusion, and the cold end-to-end primary are preserved. | `pictura-render::cold_profile_reports_first_sample_and_nested_phases`, `pictura-render::cold_engine_profile` |
| `cfc_app_sequence` | Write an 8-bit generated layered PSD with no retained source planes before child launch; use production decode/apply on a default Rust view, then a visible opacity change through Edit::Full, fixed-direction equivalent full edits, and region refresh. Inspect open-stage accounting, pixels, composite count, and boundary. | Production opening includes its preparation and opening composite; no caches are purged; the first edit changes pixels and runs exactly one full composite; opening/first-edit/repeated/region values, the cold end-to-end primary, and matching-state digests are separate. | `pictura-app::first_full_edit_follows_production_open`, `pictura-app::first_full_edit_profile` |
| `cfc_backend` | Exercise unsupported/unavailable GPU report paths and run CPU/GPU-request children independently. Inspect requested versus executed backend and fallback reason. | Requested and actual backend plus decline reason are honest; fallback and actual GPU cohorts remain separate. | `pictura-render::cold_profile_reports_backend_fallback`, `pictura-render::cold_engine_profile`, `pictura-app::first_full_edit_profile` |
| `cfc_private_input` | Supply generated temporary local input through `PICTURA_PROFILE_PSD` with a sentinel filename/layer name; exercise success, unset, missing, incompatible edit target, and failed-child results. Inspect stdout, stderr, and report fields. | Only anonymous ids and generic errors appear; set-but-missing or incompatible input exits unsuccessfully and never skips, substitutes a generated result, or records input content. | `pictura-app::profile_local_input_errors_are_redacted` |
| `cfc_compare` | Use matched fabricated reports with primary improvement greater than 2*V and unchanged controls, primary regression, and each control regression in turn. Include odd/even doubled medians and strict threshold boundaries. | Fixed improved/regressed outcomes, raw ranges/doubled medians/V, and the distinct 0/2 exits match the formula exactly. | `pictura-render::cold_profile_comparison_classifies_improvement_and_regression`, `pictura-render::cold_profile_comparison_exit_codes`, `pictura-render::cold_compare_exit_codes` |
| `cfc_compare_invalid` | Provide missing metrics, nonfinite/negative/fractional durations, unmatched protocols/input/edit recipe/build/host/threads/backend/metrics mode, and zero/two independent samples. | Malformed/mismatched data is invalid; otherwise-valid sets below three are insufficient; neither can pass, and exits are the distinct 5/4. | `pictura-render::cold_profile_comparison_rejects_invalid_and_insufficient`, `pictura-render::cold_profile_comparison_exit_codes`, `pictura-render::cold_compare_exit_codes` |
| `cfc_compare_inconclusive` | Provide a range above and exactly at the integer noise limit, overlapping improvements at/under 2*V, identical sets, zero median with zero and nonzero range, and noisy controls. | Above-limit noise and gains at/under 2*V are inconclusive; equality is not noisy; boundary/zero handling and precedence are deterministic; no samples are discarded and no retry occurs; exit is the distinct 3. | `pictura-render::cold_profile_comparison_marks_noise_inconclusive`, `pictura-render::cold_profile_comparison_exit_codes`, `pictura-render::cold_compare_exit_codes` |
| `cfc_exact` | Open/edit/render/save generated content with metrics on/off; compare all CPU samples and region slices, hidden preparation counters, and detailed timing retention. Run existing application metrics checks. | CPU and saved samples are exact; hidden content remains unresolved; disabled metrics retain no detailed phases. | `pictura-app::profile_metrics_preserve_open_edit_and_saved_samples`, `pictura-render::cold_phase_metrics_are_opt_in`, `pictura-render::hidden_layer_resolves_nothing`, `pictura-app::metrics_off_retains_nothing`, `pictura-app::metrics_on_and_off_composite_identically` |

No manual-only rows. Actual GPU execution is optional hardware-dependent
profiling; unavailable/fallback reporting has deterministic device-free checks.
Actual diagnostic measurement can be inconclusive without failing completion
of this prerequisite. Only a subsequent optimization change must demonstrate
an improved application outcome using the same comparator and protocol.
