# Test plan — quantified-parity-tracker

| Scenario | Steps | Expected | Coverage |
|---|---|---|---|
| `pt_linked` | Open `README.md` and `ROADMAP.md`; follow each `PARITY.md` link. | Both links resolve to the root `PARITY.md`. | `check-parity::links_present` |
| `pt_gap_register` | Pick an in-scope Partial, Missing, or Unknown row and read its Tracking cell. | It names an existing gap-register row, a GitHub issue, or a clear `follow-up:` note. | `check-parity::non_complete_tracks` |
| `pt_nongoal_tracking` | Pick a row with `Scope: non-goal` and read its Tracking cell. | It cites the ROADMAP or feasibility non-goal entry and is not required to name a gap-register row or GitHub issue. | `check-parity::non_complete_tracks` |
| `pt_no_second_register` | Inspect the tracker's incomplete in-scope rows and the repository for a competing gap register. | The tracker points to `docs/dev/doc-code-parity-gaps.md` IDs and no second gap file exists. | manual: repository-structure judgement; the reviewer checks the links and the absence of a competing register |
| `pt_baselines` | Read the baseline section and the tracker header. | CS6 Standard, CS6 Extended, and CC 28.0 each name their version or edition, the assessment date, and the assessed Pictura commit; the CC baseline cites the Adobe release note that names the November 2026 release (version 28.0). | `check-parity::baseline_header` |
| `pt_baseline_history` | Read the baseline-history table and the change diff. | The table has the current assessment row with the required fields and no duplicate assessment dates; the reviewer confirms the previous row remains in the diff. | `check-parity::baseline_history` |
| `pt_cs6_editions` | Inspect the 3D, measurement, and DICOM rows. | CS6 Standard is `N/A` with the edition reason; CS6 Extended is `Y`. | manual: edition applicability is a source assessment against docs/00-overview/cs6-editions-and-constraints.md |
| `pt_cc_retired` | Inspect the legacy 3D row and its sources. | CC is `N/A`, the Notes cell has a `retired:` reason, and an Adobe source is cited. | manual: retirement provenance is reviewed against the cited Adobe source; no machine-readable list exists |
| `pt_cc_added` | Inspect the Artboards row and its source. | CS6 cells are `N/A`, CC is `Y`, and an Adobe source establishes the CC capability. | manual: CC-only presence is reviewed against the cited Adobe source |
| `pt_cc_researched` | Sample the CC-only and retired rows. | Their Notes cite an Adobe release note or help page for the named CC release, not an inference from CS6. | manual: source provenance is a reading task |
| `pt_granularity` | Pick a category and compare its rows with the named source list. | One row per list entry; the category covers its expanded source units (File-menu/metadata/print/web-export, brush engine/dynamics/presets, Image > Adjustments plus stand-alone filters, type on path/warp/styles/font handling); no dialog control or individual option is a row. | manual: mapping rows to a category's source list is a documentation review |
| `pt_family_members` | Inspect a filter, blend-mode, or layer-style family row. | Its Notes state the present and total member counts as `members:<n>/<n>`. | manual: member counts are prose evidence; the reviewer checks the family rows |
| `pt_surface_counts` | Inspect the menu-command and toolbox-present counts beside the headline. | They are labelled diagnostics and do not change a denominator. | manual: reviewer checks the arithmetic separation in the method section |
| `pt_partial_zero` | Run the checker on a fixture containing a Partial row. | The row counts in the denominator and not in Complete; the percentage reflects zero credit. | `check-parity::partial_zero_credit` |
| `pt_in_scope` | Run the checker on `PARITY.md`. | The in-scope rows show the excluded non-goals and their own denominator; the full-product percentage remains visible. | `check-parity::in_scope_separate` |
| `pt_reconcile` | Run `python3 scripts/check-parity.py`. | The headline and category totals match the rows exactly for every baseline. | `check-parity::totals_reconcile` |
| `pt_rounding` | Run the checker on a fixture with a known fraction. | The displayed percentage is one decimal, rounded half up, with the exact numerator and denominator. | `check-parity::rounding_rule` |
| `pt_zero_denominator` | Run the checker on a fixture with no applicable rows for a baseline or the in-scope score. | The displayed score is `—`, not `0.0%`, and the checker accepts it. | `check-parity::zero_denominator` |
| `pt_complete_evidence` | Run the checker on `PARITY.md`. | Every Complete row names an evidence path that exists. | `check-parity::evidence_paths_exist` |
| `pt_verification` | Inspect the Check cells and run the checker. | Each is `automated:`, `manual:` with a reason, or `none`; automated refs resolve to existing test references and manual refs are non-empty. | `check-parity::check_field_valid` |
| `pt_no_parity_claim` | Read the headline and method. | The coverage-is-not-parity disclaimer is present and no row claims verified parity. | `check-parity::parity_disclaimer` |
| `pt_conflict_unknown` | Inspect a row the register and tree contradict; read both citations. | The row is Unknown and cites both sources until the register is corrected. | manual: conflict judgement requires reading both cited sources |
| `pt_baseline_dispute` | Inspect the disputed Lighting Effects row. | It is `Y`, `Unknown`, keeps both Adobe citations and a `conflict:<src>` note, stays in the CC denominator, and is never `N/A`. | `check-parity::conflict_applicability` |
| `pt_examples` | Read the worked-examples table. | All six required kinds are present, each naming an existing row ID and a source. | `check-parity::examples_present` |
| `pt_largest_gaps` | Read the largest-remaining-gaps section. | It names the largest full-product gaps, the categories or rows driving them, and their tracking sources. | `check-parity::largest_gaps_present` |
| `pt_update_rule` | Read the maintenance section. | It states that a feature ship or removal updates the rows and totals in the same pull request as the roadmap. | manual: contributor convention; the reviewer checks the text and the PR workflow |
| `pt_drift` | Run the checker on a fixture whose headline total is wrong. | It exits non-zero and names the mismatched total. | `check-parity::totals_reconcile` |
| `pt_duplicate_id` | Run the checker on a fixture with two rows sharing an ID. | It exits non-zero and names the duplicate. | `check-parity::duplicate_ids_rejected` |
| `pt_missing_evidence` | Run the checker on a fixture with a Complete row whose evidence path is absent. | It exits non-zero and names the missing path. | `check-parity::evidence_paths_exist` |
| `pt_na_reason` | Run the checker on a fixture with an `N/A` cell whose Notes lack a reason token. | It exits non-zero and names the unexplained N/A. | `check-parity::na_requires_reason` |
| `pt_check_wired` | Inspect the docs-only fast path and the parallel check batch of `scripts/verify-fast.sh`, and the guards workflow. | All run `check-parity.py --self-check` and `check-parity.py`, and a failure fails the gate. | `check-parity::gate_wiring_present` |
