# Spec Delta

## ADDED Requirements

### Requirement: Decode the `vsms` vector mask into the derived layer view

`read_psd` SHALL derive `Layer.vector_mask` from a layer's `'vmsk'`
additional-layer-info block when present, and otherwise from its `'vsms'`
(`VECTOR_MASK_SETTING2`) block. The effective block SHALL be chosen by
presence: `'vmsk'` wins even when its body fails to decode, and `'vsms'` SHALL
be consulted only when `'vmsk'` is absent. The `'vsms'` block SHALL use the
same version-3 body, record selectors, flags, fixed-point scaling, cubic
flattening, and derived-view rules as the `'vmsk'` decode requirement. On a
read/write round trip with no intervening authoring edit, both keys SHALL
remain in `Layer.extra_blocks` and SHALL be written back verbatim; the derived
view SHALL NOT be serialized.

When `'vsms'` is the effective block, a body whose version is not `3`, whose
records are malformed or truncated, SHALL leave `Layer.vector_mask` unset
without failing the read, and the preserved block SHALL remain intact.

#### Scenario: A `vsms`-only shape layer decodes its path [vsms_decode]

- **WHEN** `read_psd` reads a layer that carries a `vsms` block with a closed
  subpath and no `vmsk` block
- **THEN** the layer's `vector_mask` is set with the authored flags and one
  closed subpath spanning the authored geometry in document pixels

#### Scenario: `vmsk` wins when a layer carries both keys [vsms_vmsk_precedence]

- **WHEN** a layer carries both a `vmsk` and a `vsms` block with different
  closed subpaths
- **THEN** the derived `vector_mask` matches the `vmsk` block

#### Scenario: A malformed effective `vsms` block is unset and never panics [vsms_malformed]

- **WHEN** a layer's only vector-mask block is a `vsms` with a version other
  than 3, an unknown selector, or truncated records
- **THEN** `read_psd` succeeds, the layer's `vector_mask` is unset, and the raw
  block is still preserved

#### Scenario: A valid `vmsk` wins over a malformed `vsms` [vsms_precedence_malformed]

- **WHEN** a layer carries a decodable `vmsk` block and a malformed `vsms` block
- **THEN** the derived `vector_mask` comes from the `vmsk` block and both raw
  blocks are preserved

#### Scenario: A malformed `vmsk` does not fall back to `vsms` [vsms_no_fallback]

- **WHEN** a layer carries a malformed `vmsk` block and a decodable `vsms` block
- **THEN** `Layer.vector_mask` is unset and both raw blocks are preserved

#### Scenario: The `vsms` block survives the document round trip [vsms_roundtrip]

- **WHEN** a document carrying a `vsms` block is written and read back without
  an intervening authoring edit
- **THEN** the block's bytes are preserved and the reconstructed document
  equals the input

### Requirement: A `vsms` vector-mask fixture matches the independent decoder

The codec SHALL commit a generated fixture carrying a base pixel layer and a
`vscg` shape layer whose closed-rectangle `'vsms'` vector mask has no `vmsk`
block, authored with `psd-tools` and regenerated byte-stably by
`scripts/generate-fixtures.py`; existing fixtures SHALL be unchanged. A codec
test SHALL read the fixture with `pictura-codec` and assert the derived
`vector_mask` and round trip, and an oracle test SHALL read the same fixture
with `psd-tools` and assert that it reports the block as the layer's vector
mask with the authored geometry.

#### Scenario: Pictura decodes the fixture's `vsms` mask [vsms_fixture_pictura]

- **WHEN** the `vsms` fixture is read by `pictura-codec`
- **THEN** the shape layer has `vector_mask` set with one closed subpath
  covering the authored rectangle

#### Scenario: psd-tools reads the fixture's `vsms` mask [vsms_fixture_psd_tools]

- **WHEN** the fixture is parsed with `psd-tools`
- **THEN** the shape layer reports a vector mask whose closed path matches the
  authored rectangle

#### Scenario: The fixture round-trips byte-identically [vsms_fixture_roundtrip]

- **WHEN** the fixture is read and written by `pictura-codec` without an
  intervening authoring edit
- **THEN** the reconstructed document equals the input and the `vsms` block is
  byte-identical
