# Design

## Context

See `proposal.md` — Why. The decoder derives `Layer.vector_mask` from the
preserved `'vmsk'` block in `crates/pictura-codec/src/vector_mask.rs`
(`resolve_vector_masks`), and the compositor already samples that view through
`BlendCtx`'s mask gate and `composite_clipping::coverage`. A reported reference document stores the mask of a shape layer only under
`'vsms'` (`VECTOR_MASK_SETTING2`): version 3, flags 0, eight closed subpaths. The
layer's `'vscg'` solid fill therefore paints its whole rectangle, and the smart
object clipped above it is confined to that rectangle. psd-tools treats
`'vmsk'` and `'vsms'` as the same layer vector mask and prefers `'vmsk'` when
both exist.

The derived view also drives the Layers panel's vector-mask presence, thumbnail,
menu, and link state, and the renderer's shape identity. Once `'vsms'` decodes,
those consumers are reachable on an imported layer, so the authoring and shape
paths must resolve the same effective block.

## Goals / Non-Goals

**Goals:**

- Derive the vector-mask view from `'vsms'` when `'vmsk'` is absent, with
  `'vmsk'` precedence (including a malformed `'vmsk'` blocking fallback).
- Make vector-mask authoring and shape identity use the effective block, so an
  imported `'vsms'` shape deletes, rasterizes, links, toggles, and rasterizes as
  a shape without the mask returning on reload.
- Prove the behavior with a generated small fixture, a codec oracle, render
  tests for base appearance and clipping, and authoring/shape tests.
- Close #1284 and #1114 with one change.

**Non-Goals:**

- Falling back to a fill layer's `-1` alpha when no vector mask exists. The
  current spec requires a `'vscg'` fill with no vector mask to cover its layer
  rectangle, and this file does carry a mask, just under another key.
- Modeling the shape stroke (`'vstk'`) or subpath boolean operations. Coverage
  stays even-odd/non-zero per the existing vector-mask requirement.

## Decisions

### D1: Resolve `'vmsk'` then `'vsms'`, reusing the version-3 decoder

A small key lookup in `resolve_vector_masks` chooses the first present block
from `b"vmsk"` then `b"vsms"`; everything after it (version/flags validation,
record parsing, cubic flattening, fixed-point scaling, placeholder
density/feather merge) is unchanged. This matches psd-tools' precedence and
avoids duplicating a format parser. Verified against the reference file that
the `'vsms'` body is byte-for-byte the same layout the decoder already
accepts, including selector `6` and knot kinds 1/2/4/5.

Presence, not decodability, selects the key: a malformed `'vmsk'` leaves the
view unset rather than falling back to a valid `'vsms'`, matching the existing
malformed-`vmsk` behavior.

Alternative rejected: preferring `'vsms'` over `'vmsk'`. Pictura authors
`'vmsk'` for its own shape layers; when both exist the newer authored mask is
the one to trust, and psd-tools makes the same choice.

Alternative rejected: patching the renderer to fall back to the `-1` alpha for
mask-less fills. It fixes this file but changes a specified behavior for every
mask-less `'vscg'` fill and leaves the base's own appearance wrong.

### D2: Keep the raw block authoritative

On a read/write round trip the `'vsms'` block stays in `Layer.extra_blocks` and
is re-emitted verbatim by `write_extra`; the derived view is not serialized.
Authoring edits are the exception: they patch the effective block's flags or
rewrite its path, and delete/rasterize remove it. No writer change is needed.

### D3: Fixture and test placement

- A new `vector_mask_vsms.psd` fixture is generated by
  `scripts/generate-fixtures.py`: a base pixel layer and a `'vscg'` shape whose
  only mask is a closed-rectangle `'vsms'`. It carries no clipped layer;
  clipping tests append a full-canvas clipped layer in memory. Existing fixtures
  stay byte-identical.
- `crates/pictura-codec/tests/vector_mask_oracle.rs`'s psd-tools script
  currently reads only `VECTOR_MASK_SETTING1`; it gains the `'vsms'` fallback.
  The Pictura-only fixture decode and the round-trip are separate,
  non-skipping tests; only the psd-tools comparison self-skips without
  `psd-tools`.
- Codec unit tests cover precedence and malformed effective blocks without a
  fixture; render tests composite the fixture for the base and clipping
  assertions and build the equivalent `'vmsk'`/disabled variants in memory.
- Authoring and shape tests read the fixture, then exercise delete, flags/link,
  rasterize, and Rasterize Shape in memory, including a write/re-read check so
  a removed mask cannot return.

### D4: Coverage semantics stay as they are

The reference path's record field our decoder reads as a fill-rule marker is
`2`, which selects non-zero winding for all subpaths. In-memory rasterization
of the decoded path shows non-zero and even-odd produce the same coverage
here, matching the layer's baked alpha at threshold with IoU 0.9999. No
winding or operation change is needed for this change.

### D5: Authoring uses the effective block

One helper returns the layer's effective vector-mask key (`b"vmsk"` when
present, else `b"vsms"`). `set_vmsk_block`/`patch_flag`/`sync_vector_mask_block`
and the delete/rasterize/linked read paths use it. Delete and rasterize remove
every `'vmsk'` and `'vsms'` block, because removing only the effective key would
let the other key restore the mask on reload. When both keys exist, edits patch
or rewrite `'vmsk'` and leave `'vsms'` untouched, matching the read precedence.

Alternative rejected: gating the Layers panel controls to `'vmsk'`-only layers.
That keeps the menu safe but hides the reference layer's real vector mask and
diverges from Photoshop.

### D6: Shape identity accepts both keys

`shape_layer::is_shape_layer` and `layer_shape_paths` accept a `'vsms'` block as
the shape outline; `set_layer_shape_paths` writes the effective key; and
`rasterize_shape` drops both vector-mask keys. This keeps CS6's one-thumbnail
shape row, forced locks, shape transforms/crop, and Rasterize Shape working for
the reference layer instead of showing a separate vector-mask thumbnail.

## Risks / Trade-offs

- [`'vsms'` means something else in a file we have not seen] → psd-tools and
  Photoshop's additional-layer-info naming both treat it as the layer vector
  mask; the decoder is version- and selector-strict, so an unfamiliar body
  leaves the view unset instead of misrendering.
- [A layer carries both keys and they disagree] → `'vmsk'` wins, matching
  psd-tools; the change records that precedence in the codec spec.
- [Authoring an imported `'vsms'` layer changes its block] → delete and
  rasterize remove every vector-mask block, flag edits patch only the effective
  block, and the tests round-trip the document so a removed mask cannot return.
- [The 27 MB reference file cannot be a repo fixture] → tests use a generated
  fixture with the same block/key shape; the reference file was verified
  manually in memory (path coverage vs. baked alpha).

## Migration Plan

None. The change reads an already-preserved block; no project format, API, or
serialized bytes change. Rollback is reverting the key and effective-block
lookups and deleting the fixture/tests.
