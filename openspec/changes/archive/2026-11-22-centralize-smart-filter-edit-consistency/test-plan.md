# Test plan

This change has no spec scenarios (`skip_specs: true`). The rows below map the
acceptance criteria in issue #1398 and the design risks to runnable checks. The
three new `pictura-codec` tests are written by tasks 1.1-1.3; `check-test-plan.py`
passes once they exist.

| Scenario | Steps | Expected | Coverage |
|---|---|---|---|
| Insert, replace, delete, reorder, clear and toggle run through one consistency owner | Run the full edit sequence on a layer with a preserved `SoLE` block and on a typed-only embedded object | After every accepted edit the typed `filter_id`/`name`/`enabled` and order match the preserved `filterFXList`, and typed `options` match the serialized `Fltr` after the camera-raw option edit. For the preserved-block shape the block keeps the `soLE` prefix, a 4-aligned length, list order and unmodeled keys; for the typed-only shape only the typed list and the write/re-read are asserted, and both shapes yield the same typed list after a write/re-read | `pictura-codec::edit_sequence_agrees_across_preserved_and_typed_only` |
| A refused edit changes nothing | Delete and reorder out of range, delete from a preserved list that cannot follow, and edit a block with an unknown signature, snapshotting before each call | Each call is refused and the block bytes, `config_descriptor` bytes and typed `smart_filters` are unchanged | `pictura-codec::refused_edit_leaves_block_descriptor_and_typed_view_unchanged` |
| Replace validates the config signature | Replace an entry on a block whose signature is not `soLD`/`soLE` | The call returns `PsdError::Unsupported` and the layer is unchanged, like every other edit | `pictura-codec::replace_validates_the_config_signature` |
| Delete, reorder and clear round-trip on the fixture | Delete, reorder and clear on `test_with_smart_object02.psd`, write, re-read | The re-read filter list reflects each edit | `pictura-codec::reorder_delete_and_clear_round_trip_on_the_fixture` |
| Reorder refuses a preserved list that cannot follow | Reorder with a preserved list shorter than the typed view and with no `filterFXList` | Both are refused and the typed order is untouched | `pictura-codec::reorder_refuses_a_preserved_list_that_cannot_follow` |
| SoLE signature is accepted and preserved | Edit an option on a `soLE` block | The edit applies and the block still starts with `soLE` | `pictura-codec::edit_accepts_sole_signature_and_preserves_it` |
| A no-op edit preserves descriptor bytes | Re-set an option to its current value | The whole descriptor is byte-identical to the original (same length and `warp`/`classFloatRect`/`Pnt `/`filterFXStyle` class IDs) | `pictura-codec::noop_edit_preserves_config_descriptor_bytes`, `pictura-codec::edit_sequence_agrees_across_preserved_and_typed_only` |
| Append stacks a same-id filter | Append two same-id filters over a preserved descriptor and without one | Both entries are kept in order in the typed and preserved lists | `pictura-codec::append_stacks_same_id_typed`, `pictura-codec::append_stacks_same_id_preserved` |
| Replace keeps position, enable flag and blend options | Replace entry 0 of a preserved two-entry list | The entry keeps its index and `enab`, gains the new `filterID`, and keeps `blendOptions` | `pictura-codec::replace_keeps_position_flag_and_blend_options` |
| Re-attaching over a preserved filter keeps unmodeled keys | Re-attach a Camera Raw filter over an entry carrying unmodeled keys | The new `Fltr` values win, no duplicate entry is added, and unmodeled keys and `blendOptions` survive | `pictura-codec::reattach_over_a_preserved_filter_keeps_unmodeled_keys` |
| Attach handles both storage shapes and refuses non-smart layers | Attach into a preserved `SoLd`, into an embedded object with no block, and onto a layer with no smart object | The first two record the filter consistently; the third is refused without mutating | `pictura-codec::attach_inserts_into_a_preserved_sold_and_preserves_other_keys`, `pictura-codec::attach_authors_then_write_read_round_trips`, `pictura-codec::attach_errors_without_a_smart_object` |
| Toggles sync the typed view in both storage shapes | Toggle a filter and the group on the fixture and on a typed-only object | The typed flags follow; the fixture round-trips through save; typed-only authors no block in memory | `pictura-codec::fixture_toggle_enab_round_trips_and_syncs_the_typed_view`, `pictura-codec::toggle_without_a_preserved_block_updates_only_the_typed_view` |
| The filter-mask flag round-trips | Toggle `filterMaskEnable` over a preserved `SoLd` and write/re-read | The typed and preserved flags agree before and after the round trip | `pictura-codec::filter_mask_enable_flag_round_trips` |
| The duplicated protocol is gone | Grep `crates/pictura-codec/src` for `fn config_block_index` and for the prefix/pad serializer | One locate and one serializer remain, in `smart_filter/mod.rs`; no inline parse/serialize/commit copy survives in `pictura_raw/mod.rs` | manual: task 4.2 grep - static structure, not a runtime behavior |
| File-size caps hold | Run the file-size gate after the move | No over-cap file without an allowlist entry | manual: scripts/check-file-size.sh |
