# Test plan

| Scenario | Steps | Expected | Coverage |
|---|---|---|---|
| `tr_qt_durations` | Parse a Qt JUnit report through `junit_timings`, build a Qt layer carrying the suite total, render it | The suite's seconds are returned (falling back to the sum of its case times when the suite element has none), the layer keeps them, and the rendered line shows them | `report_tests::run_self_check` |
| `tr_qt_timing_store` | `collect` reads JUnit reports (and CTest's aggregate JUnit when present) and writes the store | The store holds per-suite seconds, per-function seconds, and per-entry execution time | `qt_test_timings::cmd_collect`, `qt_test_timings::self_test` |
| `tr_qt_timing_artifact` | Inspect the Qt-aware CI job for the artifact step and its three paths | The job uploads the JUnit reports, `ctest-junit.xml`, and the store as `qt-test-timings` | `qt_test_timings::check_ci_wiring` |
| `tr_qt_longest_entry` | Score entries against a quarter of the layer total | Each entry is marked `over` or `within` and carries its seconds | `qt_test_timings::longest_entry_lines`, `qt_test_timings::self_test` |
| `qth_plan_duration` | Plan from a store with a 20 s suite in a 40 s layer, its four functions measured | The suite gets two shares, its evidence names the measured seconds, and each function is in exactly one share | `qt_test_timings::shard_plan`, `qt_test_timings::self_test` |
| `qth_plan_no_empty_share` | Plan a 100 s suite whose only measured function suggests many shares | The count is capped at the function count, so no empty share is written; a declared plan with an empty share is rejected | `qt_test_timings::self_test` |
| `qth_plan_verify` | `verify` an empty share, a repeated function, and a missing suite function | Each is rejected with the suite and the reason | `qt_test_timings::plan_errors`, `qt_test_timings::self_test` |
| `qth_plan_named_functions` | Pass planned function names on a suite command line | `shardArguments` keeps the named functions unchanged; `shareRunsNothing` still flags an empty fallback share | `tst_test_support::namedFunctionsAreKept`, `tst_test_support::emptyShareRunsNothing` |
| `qth_plan_carry_forward` | Regenerate from a store missing a suite the baseline plan shards | The baseline entry keeps its count and its evidence says it was carried forward | `qt_test_timings::carry_forward`, `qt_test_timings::self_test` |
| `qth_critical_path` | Read the committed plan and the CTest registrations | More than one suite is registered in the layer, so the critical path cannot be one suite | `qt_test_timings::self_test` |
| `qth_suite_timeout` | Inspect the CMake registration for every plan entry | Each entry keeps its `TIMEOUT` property and `tst_quick_mask` keeps its raised timeout | manual: the timeout is a CTest property read from a configured build tree, recorded in design.md |
| `qth_longest_entry` | Run `report` against the retained store | No measured entry exceeds the quarter budget, or it is named as over | `qt_test_timings::longest_entry_lines`, `qt_test_timings::self_test` |
| `qth_condition_wait` | Scan a source with a justified wait and one with a bare non-zero wait | The justified wait passes; the bare one is named with its file and line | `check-qt-test-waits::wait_violations_in`, `check-qt-test-waits::self_test` |
| `qth_negative_wait` | Scan a wait asserted to prove nothing happens in a window, with its comment | The wait is accepted and kept | `check-qt-test-waits::self_test` |
| `vh_wait_guard` | Run `guard.sh` over a tree with an uncommented non-zero wait | The guard exits non-zero and names the file and line | `check-qt-test-waits::self_test`, `check-qt-test-waits::violations` |
| `qth_suite_process` | Read the CMake registration and the CTest list for the layer | Each suite has one CTest entry per share and runs in its own process; no suite is grouped into another suite's process | manual: the process/entry mapping is a configured-build observation, read from `ctest --show-only=json-v1` (design.md) |
| Configure builds the suites | Configure with `BUILD_TESTING` on | The tests subdirectory is added and every suite maps to one driver linked against `pictura_shell` and `Qt6::Test` and invalid registry entries fail configuration | manual: configure output is a build-tree observation, recorded in design.md |
| CTest runs each suite offscreen | Run a registered entry | It runs offscreen with its suite timeout | manual: `ENVIRONMENT`/`TIMEOUT` are CTest properties in the configured tree |
| CTest emits per-executable JUnit | Run a registered entry | It writes `build/qt-test-results/<entry>.xml` | `report_tests::missing_ctest_reports`, `report_tests::run_self_check` |
| Tests are optional | Configure with `BUILD_TESTING` off | No driver executable or test registration is emitted | manual: configure output is a build-tree observation, recorded in design.md |
| CTest does not wrap nextest | Inspect the registered commands | No CTest command invokes `cargo nextest` | manual: the command list is read from the configured tree |
| `.8bf reference under crates/` | Run the guard on a tree with a tracked `.8bf` reference | The guard exits non-zero and prints the offending lines | manual: unchanged guard behaviour, owned by its existing guard self-test |
| `artboard artifact under crates/` | Run the guard on a tree with an `artboard*` file | The guard exits non-zero and names the file | manual: unchanged guard behaviour, owned by its existing guard self-test |
| `docs modified without a marker` | Run the guard with a docs change and no marker | The guard exits non-zero and lists the changed files | manual: unchanged guard behaviour, owned by its existing guard self-test |
| `qth_sharded_main_isolation` | Run a sharded suite under each share and inspect its entry point | It constructs the state-home fixture before its window and enters through `shardedMain`, which is `QTEST_MAIN` plus the shard | `tst_smoke::stateHomeIsolationRestoresPriorValue` |
| Suites do not share state | Run two suites in one `ctest` invocation | Each has its own process and temporary state home | `tst_smoke::stateHomeIsolationRestoresPriorValue` |
| Each run starts clean | Write preferences in one run and rerun the suite | It starts from a clean temporary state directory | `tst_smoke::stateHomeIsolationRestoresPriorValue` |
| A pre-existing state home is restored | Set `XDG_STATE_HOME` before the fixture is destroyed | The previous value is restored, not unset | `tst_smoke::stateHomeIsolationRestoresPriorValue` |
| Clean tree | Run `guard.sh` on a tree whose waits are all justified and whose files are unchanged | The guard exits 0 including the wait check | `check-qt-test-waits::violations` |
| `qth_long_suites_sharded` | Run the four registered shares of Quick Mask and Document Navigate and compare each function list with the suite inventory | Every function appears once, with 300-second Quick Mask and 120-second Document Navigate timeouts | manual: inspect CTest registrations and the per-share JUnit reports on the same runner |
| `qth_driver_selection` | Dispatch a named suite with Qt Test arguments | Only that suite runs and receives the original arguments and exit status | `tst_test_support::driverDispatchesSelectedSuite` |
| `qth_driver_invalid` | Dispatch missing, malformed, unknown and duplicate suite selectors | The driver exits with an error before running a suite | `tst_test_support::driverRejectsInvalidSelection` |
