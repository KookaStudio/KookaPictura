# Test plan

| Scenario | Steps | Expected | Coverage |
|---|---|---|---|
| `et_one_owner` | Commit a layer change through the transaction; inspect the history count, the dirty flag and the content revision before and after. | One history state is added, the dirty flag is set, the revision advances once, and the declared compositing ran. | `pictura-app::one_commit_refreshes_captures_and_versions` |
| `et_reports_outcome` | Commit edits returning each outcome and compare the transaction's return value with the outcome the closure reported. | The returned outcome equals the outcome the mutation reported. | `pictura-app::the_declared_outcome_is_returned` |
| `et_mutation_inside` | Run a mutation inside the transaction that reports no change, on a document that already has history, a dirty flag and a known composite; then run a layer-tree command the engine refuses. | The history depth, the content revision, the composite and the dirty flag are unchanged, no history state is captured, and no change signal is emitted. | `pictura-app::a_refused_mutation_records_nothing`, `pictura-app::a_refused_layer_command_commits_nothing` |
| `et_notify_once` | Watch `PictureView::changed` with a signal spy while committing a layer command, Image ▸ Trim, Image ▸ Canvas Size, Apply Type Style and one character/paragraph style commit. | The spy counts exactly one change notification per committed edit. | `tst_edit_refresh::aCommitNotifiesOnce` |
| `et_no_double_present` | Dispatch Layer ▸ Flatten Image through the command registry and read `CommandRegistry::refreshCount()` before and after. | The counter advances by exactly one, and the handler presents nothing further after the transaction's own notification. | `tst_edit_refresh::aCommandRefreshesOnce` |
| `et_meta_presented` | Save a live selection into a channel, watching `changed` and the history count, then wait for the deferred panel refresh (up to the 120 ms `panelRefreshTimer_`) and read the Channels panel without any caller refresh. | One history state is added, the shell is notified once, and the new channel is listed in the Channels panel without the caller asking for a refresh. | `pictura-app::save_selection_notifies`, `tst_edit_refresh::aSaveSelectionNotifies` |
| `cr_one_refresh` | Dispatch a migrated layer-tree command (Flatten Image) through the command registry, reading `refreshCount()` around the call; the type-style operations are `type_api` calls and are covered by `et_notify_once`. | The command table's enablement, checked state and labels are recomputed once from the edit's notification, and the handler adds no second recomputation. | `tst_edit_refresh::aCommandRefreshesOnce` |
| `cr_history_current` | Commit a document edit and read the undo action's enabled state and label straight after the commit, with no further refresh. | The undo command is enabled and its label names the edit that was just committed. | `tst_edit_refresh::aCommittedEditShowsUndoState` |
