# Test plan

| Scenario | Steps | Expected | Coverage |
|---|---|---|---|
| `fbi_coalesced_input` | Dispatch multiple accepted viewport inputs, including wheel zoom and Rotate View, before processing the queued paint on a shown document canvas. Read the capture. | One paint record for the batch contains each input once. Paint time equals tile gather plus Qt draw. Slack matches the signed 16.6 ms calculation within serialization precision. | `tst_control_metrics::frameCoalescesViewportInput` |
| `fbi_cadence` | With a deterministic clock, finish a paint in canvas A, a paint in B, and a no-input paint in A. | A's interval uses A's first completion. Each canvas's first record omits its interval. The no-input record has zero input count and time and a null GPU presentation duration. | `tst_control_metrics::frameCadenceIsPerCanvas` |
| `fbi_late_tiles` | Hold a visible tile worker result until a viewport paint completes, then release it through the ordinary tile-completion path. | Both paints appear in order. Only the first consumes the input. Tile gather is inside the paint span and excludes the separately held worker interval. | `tst_control_metrics::frameRecordsLateTilesSeparately` |
| `fbi_screenshot` | Queue input and a GPU sample, then capture screenshots through both frame and canvas grab scopes before an eligible paint. Compare cadence and pending state. | Neither screenshot adds a frame, advances cadence, or consumes timings; the next eligible paint consumes them. | `tst_control_metrics::frameScreenshotDoesNotConsumePending` |
| `fbi_gpu_partial` | With a transformed canvas, paint a damaged region disjoint from a repaired span in a visible tile or crop, then paint that span. Include multiple repaired spans in one tile. | The first paint omits the sample; the later paint reports it once. | `tst_control_metrics::frameGpuPartialDamage` |
| `fbi_gpu_standin` | Supply timestamped reduced-level stand-ins, then draw an accepted result and separately overwrite or leave another undrawn. | Only the paint drawing accepted stand-in pixels reports its blend-pass interval. | `pictura-app::frame_gpu_standin_attribution` |
| `fbi_gpu_result` | Supply a deterministic device sample for one composite result used by several current tiles. Paint the pixels, then repaint them from cache. Also assemble a paint from two newly applied samples. | The first record carries each qualifying first-to-last blend-pass interval once, the cache repaint omits GPU duration, and multiple distinct samples sum without changing CPU slack. Later conversion, readback copy, and presentation are excluded. | `pictura-app::frame_gpu_samples_follow_drawn_tiles` |
| `fbi_gpu_absent` | Exercise a CPU fallback, a GPU result without a timestamp, a result from another source or view, and GPU results rejected or replaced before drawing. | No GPU composite field is serialized for these frames, including after a result is superseded by CPU pixels. | `pictura-app::frame_gpu_samples_ignore_unpainted_results` |
| `fbi_disabled` | Run the same viewport operations and edit in separate processes with metrics off and on. Compare the canvas pixels and deterministic save bytes. Exercise the disabled recorder directly. | Both runs produce the same output. The disabled recorder never reads its clock or retains or emits a frame. | `tst_control_metrics_off::frameCapturePreservesOutput`, `pictura-app::disabled_frame_metrics_skip_capture` |
| Snapshot after an edit | Reset, create a layer through the control method, and read `metrics`. | New Layer remains in `edits` and `phases` is populated. | `tst_control_metrics::snapshotContainsEditRecord` |
| Reset clears the totals | Create a layer, reset the metrics, and read again with no edit. | The second snapshot has empty phase totals and edit records. | `tst_control_metrics::resetClearsTotals` |
| Disabled metrics are refused | Start with metrics off and call the control method on an open document. | The method returns `refused`. | `tst_control_metrics_off::disabledIsRefused` |
| `fbi_frame_readback` | Fill the frame recorder beyond its limit and verify the serialized capture. In the Qt fixture, queue input and a GPU sample, reset before drawing, then paint. | The snapshot contains the latest 1,024 frames in order and reports the number displaced. Reset returns that snapshot and clears it. The next paint starts a new cadence baseline and excludes the pending pre-reset timing. | `pictura-app::frame_history_is_bounded_and_resettable`, `tst_control_metrics::frameResetClearsPendingTiming` |
| Reference gesture capture | On the ARCH-013 reference setup with a full-HD viewport, reset metrics, then pan continuously for five seconds on a 24 MP 8-bit RGB document and take a snapshot. Repeat for zoom and Rotate View. Read the matching canvas's paint intervals, CPU phases and slack, and record interval p95 for each run. | Each run yields enough records to report paint cadence and phase costs. Record any capture eviction or budget misses. Presentation time reads as unavailable. | manual: representative interactive cadence depends on the reference hardware, display setup, and continuous user input |
| Hardware device timestamp | On an adapter with wgpu timestamp queries, enable GPU compute and show a 2304 × 2304 8-bit RGB document with two ordinary pixel layers, including an unlocked layer covering the full document. Warm the visible tiles, reset the capture, and commit an opacity change on the full-size layer to trigger a bounded GPU region refresh. Read frame metrics after the repair paints, then repaint the same pixels from cache. | The repair paint has an attributable GPU composite duration, the cache-only repaint omits it, and both report unavailable GPU presentation time. | manual: this check needs a timestamp-capable adapter and an eligible GPU region refresh |
