# Test plan

| Scenario | Steps | Expected | Coverage |
|---|---|---|---|
| `tsu_compact` | Build the frame with the Tools panel visible and compact. Inspect the toolbox columns, the tools scroll host's vertical scroll-bar policy, and the header children. | One tool column; vertical policy is `ScrollBarAlwaysOff`; the expand double-arrow, close control, and `•••` grip are all visible. | `tst_toolbar_shape::compactLayoutHasOneColumnAndNoScrollbar` |
| `tsu_expanded` | Activate the header double-arrow, pump events, then inspect the toolbox and header. | Two tool columns; width grows; no scrollbar; grip and close stay visible; the toggle now points back to compact. | `tst_toolbar_shape::doubleArrowExpandsToTwoColumns` |
| `tsu_float_flip` | Float the expanded Tools panel, flip it to compact, then inspect every slot and the footer against the overlay bounds. | The overlay re-fits to the compact grid; the last tool slot and both footer buttons are inside the overlay with no clipping. | `tst_toolbar_shape::floatingExpandedToCompactKeepsAllTools` |
| `tsu_grip_drag` | Start a drag from the grip, move to a global point outside the frame but inside the screen, then drop on the left and right workspace edges in turn; flip 1↔2 columns while floating. | The whole column floats as a frameless top-level while outside, keeps the full tool content height and hugs its content width, and re-docks on either edge as a splitter pane. | `tst_toolbar_shape::gripDragFloatsOutsideTheWindow`, `tst_toolbar_shape::floatingModeFlipKeepsFullHeight`, `tst_toolbar_shape::floatingDragOverAppWindowStaysFloating`, `tst_toolbar_shape::bothLayoutsDockLeftAndRight` |
| `tsu_short_window` | Show the frame at the default size, then resize it below the compact layout's required height and back up. | The Tools panel is visible on startup, stays visible when the workspace is short, clips its content at the bottom, and never grows a scrollbar. | `tst_toolbar_shape::toolbarVisibleOnStartupWhenWorkspaceIsShort` |
| `tsu_float_dock_zone` | Float the Tools panel, drag it to a point beside the app window outside the workspace, then into the workspace's left edge band. | The desktop drag draws no dock indicator and stays floating; the edge-band drag shows the indicator and re-docks on the left. | `tst_toolbar_shape::floatingDragBesideAppWindowStaysFloating` |
| `tsu_close` | Activate the header close control while docked and while floating, then trigger `Window > Panels > Tools`. | The tools column hides, a floating overlay is torn down, and the Window action shows it again docked in the same layout. | `tst_toolbar_shape::closeHidesAndWindowMenuRestores`, `tst_toolbar_shape::closeFloatingToolbarRemovesOverlay` |
| Existing left/right placement still holds | Run the existing workspace and screen-mode suites. | The Tools column keeps its side/index and remains a splitter pane across workspace applies. | `tst_workspaces::toolsColumnLeftBranch`, `tst_screen_modes::fullWithMenuBarKeepsPanels` |
| Header grip look on a real screen | Open the app on a real X11/Wayland display and inspect the compact and expanded headers. | The grip reads as `•••`, the double-arrow points to the layout it expands to, and the close `×` is at the right. | manual: offscreen Qt Test can assert widget existence and geometry but not the rendered glyph shape on a real compositor. |
