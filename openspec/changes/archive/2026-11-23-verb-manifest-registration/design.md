# Design

## Context

See `proposal.md` — Why. The constraints that shape this design:

- `cxx-qt-build 0.10` requires each bridge file to be passed to
  `CxxQtBuilder::files([...])`; the list is 74 hand-written lines in
  `crates/pictura-app/build.rs`.
- `.crate_include_root(None)` is deliberate: with the default include root,
  Cargo watched the whole crate directory, so touching any shell source reran
  the build script. Removing it is what makes a non-bridge Rust edit cost 5.3 s
  of cargo time instead of 13.2 s (`docs/dev/STATE.md`, #1042).
- The build script already tracks content instead of timestamps in two places:
  `restore_unchanged_headers` restores generated-header mtimes when a rerun
  produces identical content, and CMake rewrites `pictura_bridge.stamp` only
  when the hashed bridge modules change.
- `crates/pictura-app/src/build_config.rs` (826 lines after this change,
  test-only) already parses bridge modules: `bridge_modules_end_at_column_zero`,
  `brace_counted_end`, `bridge_module`, `rust_function_count`, `bridge_files`,
  `membrane_headers`. It is already a `build_config/` module tree
  (`view_oracle.rs` is a submodule), so the two generators land as submodules;
  the shared owner helpers (`adapter_owner_files`, `owner_generated_includes`,
  `header_owner_lists`, `bridge_header_owners`) grow the parent file rather than
  duplicating the scan.
- The `actions-bundle` design (decision 2) chose a checked-in generated
  artifact plus a Rust drift test over build-time generation, "to avoid more
  CMake/build-order surface". `crates/pictura-script/tests/golden/*.tsv` is the
  shipped instance of that pattern.
- The tree has 74 bridge files. `openspec/specs/ui/view-seam-adapters` and
  `docs/dev/{STATE.md,refactor-view-seam.md}` still state 69.

## Goals / Non-Goals

**Goals:**

- A new bridge is registered by creating its Rust source and adding its
  generated header to one membrane. No edit to `build.rs`.
- A verb's owning `cpp/api/` header and its C++ name are readable from one
  checked-in file, without reading generated headers or grepping.
- The manifest and the bridge sources cannot disagree without a red gate.
- A non-bridge Rust edit keeps its current cargo cost.

**Non-Goals:**

- Regenerating membranes, or deriving the membrane grouping from verb names.
  The grouping is editorial and already correct (measured over-inclusion: 24 of
  688 membrane includes across 420 translation units, 3%).
- Replacing the global bridge stamp with per-membrane stamps. `bridge-membranes`
  made the fan-out global on purpose because a translation unit can reach a
  membrane through `frame_includes.h`, which `OBJECT_DEPENDS` cannot express.
- Making the manifest a runtime or C++ build input.
- Pruning verbs with no caller. The manifest makes them visible; deleting them
  is a separate change.

## Decisions

### Decision: a checked-in bridge-source list, not a build-time scan

`build.rs` reads `crates/pictura-app/bridge_sources.txt` and passes its entries
to `.files(...)`; the 74-line inline list is deleted. The file is generated by a
blessable test in `build_config/bridge_sources.rs` and emitted sorted, one
crate-relative path per line.

Why a file and not a scan. A build-time scan of `src/` requires the build script
to watch the directory, and Cargo then reruns the script on *every* Rust edit —
a 10x cargo regression on the most common edit (#1042 measurements: 5.3 s ->
~55 s). Suppressing the codegen on a rerun is not an out: `CxxQtBuilder::build()`
is the only emitter of this crate's `rustc-link-lib` for Qt
(`qt-build-utils/src/parse_cflags.rs:158`), `rustc-cfg=cxxqt_qt_version_major`
(`cfg.rs:110`), the `-fuse-ld` link arg (`platform.rs:25-53`) and the
`cc_builder.compile(&static_lib_name())` edge (`cxx-qt-build/src/lib.rs:1359`).
Cargo replaces a build script's captured directives on every rerun, so a rerun
that returns before `build()` leaves the next link without Qt. The list keeps
`build()` unconditional and untouched.

The list also keeps `meta/build-performance`'s rerun guarantee intact: the script
watches the list and the sources the list names, exactly as it watched the
hand-written list's files before, and never watches the rest of `src/`.

**Alternatives rejected:** watching `src/` (reruns on every Rust edit; breaks
`bp_bridge_impl_no_rerun`); watching `src/` and skipping `build()` (drops the
link and cfg directives); discovering bridges at configure time only (CMake
already does this, but `build.rs` still needs the list, and a stale list would
silently drop a bridge's headers).

### Decision: one scanner, two artifacts

`build_config.rs` already walks `src/` for the bridge marker (`bridge_files`),
parses each bridge module (`bridge_module`, `brace_counted_end`) and knows which
`cpp/api/` file owns each generated header (`header_owner_lists`). Both the
bridge list and the verb manifest are projections of that one scan: the list is
the bridges' paths, the manifest is their declared verbs. No new parser, no new
script, no new dependency.

Both artifacts are blessed the same way — set the artifact's environment
variable and run the test (`PICTURA_WRITE_BRIDGE_SOURCES=1`,
`PICTURA_WRITE_VERB_MANIFEST=1`) — and both have a drift test that names the
missing and stale entries.

### Decision: one manifest, checked in, generated by a blessable test

The manifest is `crates/pictura-app/src/build_config/verb_manifest.tsv`, read
with `include_str!` and rewritten in place when `PICTURA_WRITE_VERB_MANIFEST=1`
is set. The generator lives in `build_config/verb_manifest.rs` and reuses the
existing block/attribute helpers; no new parser, script, CI job, or dependency.

Rows are `kind`, `cpp_name`, `rust_name`, `owner`, `bridge`, sorted by
`(owner, kind, cpp_name, rust_name)`; the first four lines are comments naming
the columns and the regeneration command, followed by the column header:

```
qsignal	changed	changed	api/view_bridge.h	pictura_app/src/cxxqt_object.cxxqt.h
qsignal	layerVisibilityChanged	layer_visibility_changed	api/view_bridge.h	pictura_app/src/cxxqt_object.cxxqt.h
free	guide_count	guide_count	api/document_bridge.h	pictura_app/src/cxxqt_object/guides.cxxqt.h
```

`kind` is `free` for `extern "Rust"` functions, `qinvokable`, or `qsignal`.
`owner` is the file under `cpp/api/` whose includes name the bridge's generated
header: one of the domain membranes, or `api/type_api.h` / `api/type_api.cpp`
for the `type_tools` headers, which the type adapter owns as the existing
type-adapter requirement allows. There is no "unowned" case: a bridge that
declares no verb produces no rows, and a bridge that does declare one must have
an owner or the manifest test panics naming it. A C++ name declared twice stays
two rows; `bridge` and `rust_name` disambiguate. The shipped instance is
`commit_move` (`cxxqt_object.rs:939`) and `commit_move_legacy` with
`#[cxx_name = "commit_move"]` (`:945-946`), which is why the uniqueness key is
`(owner, kind, cpp_name, rust_name)` and not `cpp_name`.

Rows are collected by splitting each `extern "Rust"`/`extern "RustQt"` block on
`fn` lines rather than on an attribute pattern, so a doc comment or an
unrecognised attribute cannot drop a verb. A test asserts the row count equals
the number of `fn` lines in those blocks across the tree, so a parser bug
surfaces as a count mismatch instead of a silently short manifest.

**Alternatives rejected:** build-time generation (reopens the build-order
surface `actions-bundle` closed, and makes the mapping unreadable without a
build); a Python generator under `scripts/` (a second declaration parser to
keep in step with Rust); generating on demand only in CI (the file must be in
the tree to be discoverable).

### Decision: two drift tests replace the inline-list equality check

`bridge_count_within_budget` asserts `build.rs`'s `.files([...])` equals the
bridge files on disk. That assertion survives, sourced from
`bridge_sources.txt` instead of parsing `build.rs` text: the list's drift test
holds the file identical to the discovered bridges, and the budget test holds
`build.rs` free of an inline `"src/…"` list. `listed_bridge_files()`, which
parsed `build.rs`, is deleted; `bridge_files_hold_declarations_only` iterates
the discovered set instead. `bridge_count_within_budget` keeps the count (74)
and `cxxqt_object.rs` (1,204) ratchets.

The verb drift test is a second, independent ratchet: it fails when the
checked-in manifest and the declared verbs differ, naming missing, extra, and
changed rows. Its row-count assertion is against `rust_function_count`, the
pre-existing counter, not against the row builder's own split, so a parser bug
cannot cancel itself out.

### Decision: record the shipped bridge budget

The budget was written as 69 when `bridge-membranes` landed at `f3dc0448`; the
tree is at 74 after six bridges landed (`app_runtime_bridge`, `auto_align`,
`fade`, `layer_comps`, `proofing`, `preferences_bridge`) and one was removed
(`gpu_probe_bridge`). `build_config.rs`, `docs/dev/STATE.md`, and
`docs/dev/refactor-view-seam.md` record 74 and stay shrink-only; this change's
delta records 74, and the main `ui/view-seam-adapters` spec reaches it only when
the change is archived. Leaving 69 in the spec would mean the gate has been
failing its own written contract since those bridges landed, which is worse than
a bumped ceiling that only shrinks.

## Risks / Trade-offs

- **[A bridge is added but the list is not regenerated]** → This is the one real
  cost of a checked-in list over a scan: the bridge would build only after the
  drift test is satisfied, and until then its generated header is missing, which
  is a loud compile error at the membrane, not a silent miscompile. The drift
  test names the unlisted file, and its message carries the regeneration
  command.
- **[The list and the manifests drift apart in a PR]** → Both are drift-tested in
  the same nextest run `verify-fast` already executes; blessing is explicit
  (`PICTURA_WRITE_BRIDGE_SOURCES=1`, `PICTURA_WRITE_VERB_MANIFEST=1`), so a
  normal test run can never rewrite them.
- **[The manifest parser silently drops a `fn`]** → The row count is asserted
  against `rust_function_count`, the pre-existing counter that reads the same
  blocks a different way, and the shipped count is 1,465.
- **[The attribute walk collects a neighbouring declaration's attributes]** →
  It stops at the first line that is not `#[...]`, so a doc comment or a blank
  line between declarations ends it. Measured against the tree this yields
  exactly the 10 `#[cxx_name]` verbs and 12 signals; a walk that continued
  through doc comments would over-attribute and change those counts.
- **[A duplicated C++ name makes a row ambiguous]** → `commit_move` is declared
  twice (once as `commit_move_legacy` with `#[cxx_name]`); the uniqueness key is
  `(owner, kind, cpp_name, rust_name)`, so both rows survive and stay distinct.
- **[Spec/docs drift recurs for the next bridge]** → The budget lives in one
  place (`build_config.rs`); the docs line is refreshed in this change.

## Migration Plan

1. Add `build_config/verb_manifest.rs` with its tests; bless
   `src/build_config/verb_manifest.tsv` and verify the row count is 1,465.
2. Add `build_config/bridge_sources.rs` with its tests; bless
   `bridge_sources.txt` and verify it lists the same 74 files the inline list
   did.
3. Point `build.rs` at the list, delete the inline list, and add the
   `rerun-if-changed` for it; confirm the generated headers are byte-identical
   and no new `src/` path is watched.
4. Re-source `bridge_count_within_budget` and
   `bridge_files_hold_declarations_only` from the discovered set; delete
   `listed_bridge_files`.
5. Update the ratchet spec, `docs/dev/STATE.md` and
   `docs/dev/refactor-view-seam.md`; commit the docs with `TASK-ALLOWS-DOCS`.
6. Archive the change and run `bash scripts/verify-full.sh` plus
   `openspec validate --all --strict`.

Steps 1 and 2 are additive and revertible on their own. Step 3 is one edit plus
one deletion; reverting it restores the inline list, and the list file then
becomes unreferenced but still drift-tested, so the revert is a two-line change.

## Open Questions

- Whether the manifest should later feed a generated `verb → include` helper
  header for C++ callers. Not needed while the membrane set is stable; it would
  be a second consumer of the same rows.
