# Test plan

Planning coverage for #1344. Each row corresponds to one scenario in a delta
spec, including unchanged scenarios retained inside a MODIFIED requirement.
Repeated untagged titles have separate rows with their own steps and expected
results. No manual-only scenarios are required: the data, file, render, and UI
assertions can run as Rust or offscreen Qt Test checks.

Coverage names identify the automated test sources written during apply; they
are not execution results. Existing coverage was migrated to typed access with
its original assertions retained. The focused plan-cell unquoting change and
parser regression sources are also written. Builds, test execution, formatting,
validation, and evidence collection are delegated to CI at the user's request.
Main-spec sync and archival are complete; the coverage below remains planned
coverage until CI reports execution results.
Existing OpenSpec scenario titles are intentionally retained.

The route/output corpus uses existing fixtures, known-value expectations, and
pre-migration evidence, never expectations generated by the new resolver.
Serialized comparisons use established writer goldens and original block bytes;
whole-file identity is asserted only where the existing writer guarantees it.
No fixture or golden is regenerated. Optional external oracles retain their
normal self-skip policy and must report their actual availability.

Mask-transition rows cover Fill↔Shape without changing Pixel-mask behavior;
effective raw-key presence, command-specific mask results, saved flags, and
UI/file/history state are asserted explicitly. Import-admission rows cover
new raw/DOM/parser temporaries as well as retained tables on hidden layers.
They distinguish malformed-payload preservation from typed resource refusal
and prove refusal before excess allocation. The core manifest check stays
core-only; the downstream adjust check proves re-export type identity.
