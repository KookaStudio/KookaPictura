# Test Plan

One row per scenario in the change's spec deltas. Coverage names an automated
test, or `manual:` with the reason it cannot be automated. Existing canvas-drop
behaviour is covered by the C++ self-test and is not changed by this work.

| Scenario | Steps | Expected result | Coverage |
|---|---|---|---|
| Success records one state and returns the layer path | Choose a PSD in `File > Place…` with a document open and commit the transform | One `"Place"` state and one new layer; the UI test does not observe the bridge `QString` return (the direct bridge return is covered by self-test code 279) | `tst_place_sequence::mixedFormatsPlacePerFile` |
| A raster image records one state and returns the layer path | Choose a PNG in `File > Place…` and commit the transform | One `"Place"` state and one new smart-object layer; the UI test does not observe the bridge `QString` return, which self-test code 290 (`lpr_image_import`) covers | `tst_place_sequence::multiSelectPlacesOneLayerPerFile` |
| A successful place starts a transform session | Place a supported image and inspect the session state | `transform_session_active()` is true on the new layer and the `"Place"` state remains | `tst_place_sequence::eachPlaceWaitsForThePreviousTransform` |
| Refusal records nothing | Select an undecodable raster among good files and finish the batch | The failed file adds no layer or state and the good files still place | `tst_place_sequence::failedFileDoesNotStopTheRestAndIsSummarized` |
| Enabled only when a document is open | Enable and dispatch `file.place` with no document | The action is disabled, no Place dialog opens, and the dispatch is a no-op | `tst_place_sequence::placeUnavailableWithoutDocument` |
| place_dialog_filters | Open `File > Place…` with a document active and inspect the filter list and mode | The dialog offers `Images (…)` beside the Photoshop entries and accepts a multi-file selection | `tst_place_sequence::placeDialogOffersImagesFilter` |
| place_multi | Select two PNGs in `File > Place…`; commit each Free Transform | Two layers, two `"Place"` states, dialog order preserved, no session at the end | `tst_place_sequence::multiSelectPlacesOneLayerPerFile` |
| place_multi_mixed | Select a PSD and a PNG; commit the PSD session as an identity transform (no gesture) and commit the PNG session | The PSD remains natively embedded with its original payload; the PNG is placed through the raster bridge | `tst_place_sequence::mixedFormatsPlacePerFile` |
| place_multi_partial | Select a good PNG, an undecodable raster, and another good PNG; commit the good sessions | Two layers and two states; one summary dialog names the undecodable file | `tst_place_sequence::failedFileDoesNotStopTheRestAndIsSummarized` |
| place_multi_all_failed | Select only files that cannot be placed and finish the batch | No layer or history state is added and one summary dialog names every failed file | `tst_place_sequence::allFilesFailShowsOneSummary` |
| place_multi_cancelled | Select a mismatched raster and a good raster; cancel the profile warning for the first | The first records nothing; the good file places; the summary does not list the cancelled file | `tst_place_sequence::cancelledProfileWarningSkipsWithoutSummary` |
| place_multi_profile_policy | Set a policy override, place a missing file, then place a tagged raster | The second file uses the default policy, not the failed file's choice | `tst_place_sequence::failedPlaceDoesNotReuseTheProfilePolicy` |
| place_multi_no_document | With no active document or during an active transform, inspect and dispatch `file.place` | The action is disabled, no Place dialog opens, and no placement starts in either case | `tst_place_sequence::placeUnavailableWithoutDocument`, `tst_place_sequence::placeUnavailableDuringTransform` |
| Menu Place enters the session | Place a supported image through the menu command | A Free Transform session begins on the new layer and the `"Place"` state remains | `tst_place_sequence::eachPlaceWaitsForThePreviousTransform` |
| Canvas drop enters the session | Drop one or more supported files on the canvas | One session begins on the last placed layer; every placed layer keeps its `"Place"` state | manual: self-test code 291 covers every placed layer's `"Place"` state and code 292 covers the single-file session entry; the multi-file last-placed session target is not directly asserted |
| Cancelling keeps the placement | Start a canvas-drop session and cancel the session | The placed layer remains and its `"Place"` state remains | manual: self-test code 292 covers the single-file canvas-drop cancel with an unchanged history; it does not assert the multi-file last-layer target |
| ft_menu_multi_place | Place two files; while the first session is active, inspect the layer count; commit with Enter or the apply control; inspect again | The second layer does not exist until the first session ends; the second session then starts | `tst_place_sequence::eachPlaceWaitsForThePreviousTransform`, `tst_place_sequence::applyControlCommitsAndAdvances` |
| ft_menu_place_escape | Place a file, press Escape or click the transform's Cancel control, inspect the layer and history | The just-placed layer and its `"Place"` state are removed | `tst_place_sequence::escRemovesThePlacementAndHistory`, `tst_place_sequence::cancelControlRemovesThePlacement` |
| ft_menu_place_escape_next | Place two files, press Escape or the Cancel control on the first, choose Continue | The first placement is removed and the second file is placed and transformed | `tst_place_sequence::escContinuePlacesTheNextFile` |
| ft_menu_place_escape_last | Place two files, commit the first, press Escape or the Cancel control on the last | The last placement is removed and no cancel/continue dialog appears | `tst_place_sequence::escOnLastItemEndsWithoutDialog` |
| ft_menu_place_escape_whole | Place two files, press Escape or the Cancel control on the first, choose Cancel the whole Place | No further file is placed and no summary dialog appears | `tst_place_sequence::escCancelWholeStopsTheBatch` |
| ft_tool_switch_dont_apply | Place two files; during the first session, choose another tool and answer Don't Apply | The first placed layer and its `"Place"` state remain and the second file is placed | `tst_place_sequence::toolSwitchDontApplyKeepsThePlacement` |
| ft_menu_place_identity_commit | Place two files; commit the first session without changing the transform | No `"Free Transform"` state is added and the second file is placed | `tst_place_sequence::identityCommitAdvancesWithoutHistory` |
| ft_menu_place_document_switch | Place two files; while the first session is pending, activate another document | The batch stops, the original document keeps its placed layers, and no summary dialog appears | `tst_place_sequence::documentSwitchAbortsTheBatch` |
| ft_menu_place_document_close | Place two files; while the first session is pending, close the document | The batch stops and no summary dialog appears | `tst_place_sequence::closingDocumentAbortsTheBatch` |
