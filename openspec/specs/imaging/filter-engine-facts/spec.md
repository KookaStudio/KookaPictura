# filter-engine-facts Specification

## Purpose

The per-variant engine facts — which engine applies a filter, whether its kernel moves the alpha plane, how wide a preview apron it needs, whether its CPU path beats the GPU round trip — are decided exhaustively on the filter type, and the coverage tests iterate the variants the type declares instead of a hand-written list.

## Requirements

### Requirement: Per-variant engine facts are decided for every variant

The filter type SHALL expose each per-variant engine fact as a query on a filter value or a filter kind: whether the kernel moves the alpha plane, the preview apron, whether the row-parallel CPU path outruns the GPU round trip, and which engine applies the variant. Every variant of the type SHALL have a decision for every fact, and that SHALL be enforced by the compiler — a variant added to the type SHALL NOT compile until each fact is decided for it. The facts SHALL hold the values they hold today, so no filter's rendered output changes.

#### Scenario: A new variant does not compile until every fact is decided [fef_new_variant_needs_every_fact]

- **WHEN** a variant is added to the filter type and to the generated list, and one of its facts is not decided for it
- **THEN** the crate does not compile; the compiler reports the variant whose match arm is missing

#### Scenario: A filter reports its own facts [fef_filter_reports_its_facts]

- **WHEN** a filter is asked for its facts
- **THEN** a Gaussian Blur of radius 16 reports that its kernel moves the alpha plane, that its preview apron is 16 pixels, and that the crate's own kernel applies it, while Solarize reports that its kernel leaves the alpha plane alone and needs the default apron of 128 pixels

### Requirement: The variant list is generated and checked against the filter type

The filter crate SHALL expose the filter variants as a list generated by a single macro table, and the compiler SHALL reject that list when it drifts from the type in either direction: a variant of the type missing from the list and a name in the list that is not a variant of the type SHALL each fail to compile. The generated list SHALL name every variant exactly once and SHALL carry the engine that applies the variant.

#### Scenario: The generated list names every variant once [fef_variant_list_covers_type]

- **WHEN** the generated variant list is read
- **THEN** it holds one entry per variant of the filter type, with no name repeated, and each entry names the engine that applies that variant

#### Scenario: A variant missing from the list does not compile [fef_variant_list_drift_fails]

- **WHEN** a variant is added to the filter type without being added to the generated list
- **THEN** the crate does not compile, naming the variant that the list does not cover

### Requirement: Each variant is applied by exactly one engine

Every filter variant SHALL be applied by exactly one engine — the filter crate's own kernel or the ported engine — and the engine SHALL be a queryable property of the variant. Both engines' implementations SHALL name every variant, so a variant that neither implementation names SHALL NOT compile. A variant that the property assigns to an engine which does not implement it SHALL fail at run time with an unsupported-filter error rather than apply another kernel's result.

#### Scenario: Each variant is applied by the engine its property names [fef_engine_matches_implementation]

- **WHEN** every variant in the generated list is applied to a buffer
- **THEN** each is applied by the engine its entry names and none is refused as unsupported, and no variant is applied by both engines or by neither

#### Scenario: A variant with no implementation does not compile [fef_missing_implementation_fails]

- **WHEN** a variant is added to the filter type and to the generated list, and neither engine's implementation names it
- **THEN** the crate does not compile; the compiler reports the match that omits the variant

### Requirement: The oracle coverage test accounts for every variant

The oracle mapping test SHALL hold exactly one row per filter variant, and SHALL fail when a variant has no row. Each row SHALL state the ImageMagick operator that is that variant's oracle, or state that the variant has none and carry a non-empty note saying why. The test SHALL iterate the generated variant list rather than a list written by hand.

#### Scenario: The mapping table holds one row per variant [fef_mapping_covers_every_variant]

- **WHEN** the oracle mapping test runs
- **THEN** it holds exactly one row per variant in the generated list, and fails when a variant has no row or two rows

#### Scenario: Every row states an oracle or states that it has none [fef_mapping_row_states_oracle]

- **WHEN** the oracle mapping test runs
- **THEN** every row names an ImageMagick operator with a tolerance, or names no operator and carries a non-empty note stating why it has none

### Requirement: The ported and digest coverage tests decide every variant

The ported-engine contract test SHALL cover every variant the engine property assigns to the ported engine. The kernel-digest test SHALL record a digest for every variant whose kernel runs row-parallel and SHALL record explicitly that a variant has none. Both SHALL iterate the generated variant list.

#### Scenario: The ported cases cover every ported variant [fef_ported_cases_cover_every_variant]

- **WHEN** the ported-engine contract test runs
- **THEN** it holds a case for every variant the generated list assigns to the ported engine, and fails when one is missing

#### Scenario: Every variant has a digest decision [fef_digest_decides_every_variant]

- **WHEN** the kernel-digest test runs
- **THEN** every variant in the generated list either carries a recorded digest or is recorded as having none, and the test fails when a variant is undecided

### Requirement: The moving-alpha set and the moving-kernel fixture agree

The set of variants whose kernel moves the alpha plane SHALL be a decision on the generated variant list, and the fixture the render crate's alpha tests use SHALL hold one instance of exactly those variants. A variant whose kernel moves the alpha plane only in some of its settings SHALL be counted as moving, and its exception stated in the decision.

#### Scenario: The moving fixture covers exactly the moving variants [fef_moving_fixture_matches_set]

- **WHEN** the render crate's alpha tests compare their moving-kernel fixture against the moving-alpha set
- **THEN** the fixture holds one instance of every variant in the set and none of the others, and the comparison fails when the two differ
